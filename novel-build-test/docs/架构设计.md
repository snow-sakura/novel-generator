## 二、AI-Native 4 支柱架构

```
                    ┌──────────────────┐
                    │   用户请求/事件    │
                    └────────┬─────────┘
                             │
              ┌──────────────▼──────────────┐
              │       事件总线 (Redis)        │
              │   异步消息 / 任务队列 / 通知   │
              └──────────────┬──────────────┘
                             │
         ┌───────────────────┼───────────────────┐
         ▼                   ▼                   ▼
  ┌─────────────┐   ┌──────────────┐   ┌──────────────┐
  │  向量数据库   │   │  MCP 协议集成 │   │  RAG 知识管道 │
  │  (Qdrant)   │   │  (工具扩展)   │   │  (检索增强)   │
  │             │   │              │   │              │
  │ • 语义检索  │   │ • Playwright │   │ • 文档解析   │
  │ • 相似度匹配 │   │ • BrowserStack│   │ • 文本分块   │
  │ • 知识存储  │   │ • Maestro    │   │ • 向量化存储  │
  └─────────────┘   └──────────────┘   └──────────────┘
```

### 2.1 向量数据库 (Qdrant)

- 存储 AI 知识库、测试用例嵌入、执行历史
- 按项目隔离集合（`project:{id}_knowledge`）
- 嵌入维度：384（哈希降级编码器）
- 支持 CRUD + 语义检索

### 2.2 事件总线 (Redis)

- 智能体间消息传递
- 异步任务队列
- 系统事件通知
- Pub/Sub 模式

### 2.3 MCP 协议集成

- MCP 工具注册与发现
- Playwright 浏览器自动化
- BrowserStack 跨浏览器测试
- Maestro 移动端测试

### 2.4 RAG 知识管道

- 文档自动分块与向量化
- 语义检索与重排序
- 项目级知识库隔离
- 支持多格式文档（MD/PDF/TXT）

```
     └────────────┘  └────────────┘  └────────────┘
              │              │
              ▼              ▼
     ┌──────────────────────────────────────┐
     │           智能体池                     │
     │  ┌──────┐ ┌──────┐ ┌──────┐ ┌──────┐ │
     │  │需求分析│ │测试架构│ │测试设计│ │用例编写│ │
     │  └──────┘ └──────┘ └──────┘ └──────┘ │
     │  ┌──────┐ ┌──────┐ ┌──────┐          │
     │  │执行分析│ │质量审计│ │成本优化│          │
     │  └──────┘ └──────┘ └──────┘          │
     └──────────────────────────────────────┘
```

### 3.1 LangGraph 工作流定义（7 步流程）

```
[需求分析] ──→ [测试架构] ──→ [测试设计] ──→ [用例编写]
                                                      │
                                                      ▼
[成本优化] ←── [质量审计] ←── [执行分析] ←────────────┘
```

- **需求分析**: 解析需求文档，提取测试要点
- **测试架构**: 设计测试架构，选择测试策略
- **测试设计**: 设计测试场景，编写测试方案
- **用例编写**: 生成测试用例，维护用例库
- **执行分析**: 执行测试，收集结果，分析失败
- **质量审计**: 质量评估，合规检查，最终报告
- **成本优化**: 跟踪 Token 消耗，优化模型选择

### 3.2 AutoGen 辩论引擎

```
┌─── 分歧发现 ──→ 第1轮辩论 ──→ 第2轮辩论 ──→ 第3轮辩论 ──→ 共识检查 ──→ 调度仲裁
```

- 2~3 个模型对同一决策进行辩论
- 最大 3 轮辩论后检查共识
- 未达成共识时由调度总控仲裁

## 四、模型分级策略

| 层级 | 模型 | 单价 | 适用场景 | 预计占比 |
|------|------|------|---------|---------|
| L1 | DeepSeek-V3 | ¥1/M tokens | 常规任务：需求分析、用例生成、报告编写 | 70% |
| L2 | DeepSeek-R1 | ¥2/M tokens | 推理审计：质量审计、辩论、缺陷分析 | 15% |
| L3 | GLM-4 | ¥15/M tokens | 结构化输出：测试计划、架构设计 | 10% |
| L4 | Qwen-Max | ¥20/M tokens | 复杂决策：架构评审、重大缺陷判定 | 5% |

### 成本优化 5 层策略

1. **模型分级**: 70% 常规任务用 L1 廉价模型
2. **结果缓存**: Redis 缓存相同查询结果（TTL 24h）
3. **批量处理**: 合并多个小任务为单个请求
4. **增量更新**: 仅对变更部分重新生成
5. **结构化输出**: 使用 JSON 模式减少 Token 消耗

## 六、API 设计规范

- **基础路径**: `/api/v1`
- **认证方式**: JWT Bearer Token
- **分页参数**: `page`(默认1), `page_size`(默认20, 最大100)
- **响应格式**:

```json
{
  "items": [],
  "total": 100,
  "page": 1,
  "page_size": 20,
  "total_pages": 5
}
```

- **错误格式**:

```json
{
  "detail": "错误描述信息"
}
```
