# V1/V2 版本标识改造计划

## 目标
为 V1 和 V2 版本添加明确的版本标识，避免与未来 V3+ 版本混淆。涉及数据库、后端、前端、文档四个层面。

---

## 一、V1 版本修改

### 1.1 数据库
- **文件名**: `novel_generator.db` → `novel_generator_v1.db`
- **修改文件**: `v1/backend/app/config.py`
  - 默认 `DATABASE_URL` 改为 `sqlite:///./novel_generator_v1.db`
- **修改文件**: `v1/backend/.env.example`
  - `DATABASE_URL=sqlite:///./novel_generator_v1.db`

### 1.2 后端
- **修改文件**: `v1/backend/app/main.py`
  - FastAPI version 改为 `"v1.3.1"`
  - 根路由返回 `"番茄小说生成智能体 V1 API"`
- **修改文件**: `v1/backend/app/routers/generate.py`
  - 所有 API 路由已使用 `/api/v1` 前缀，无需修改

### 1.3 前端
- **修改文件**: `v1/frontend/src/App.jsx`
  - 导航栏标题改为 `"番茄小说生成器 V1"`
- **修改文件**: `v1/frontend/package.json`
  - name 改为 `"novel-generator-v1-frontend"`

### 1.4 文档
- **修改文件**: `v1/README.md` — 标题确认为 "V1"
- **修改文件**: `v1/CLAUDE.md` — 添加 V1 标识
- **修改文件**: `v1/AGENTS.md` — 添加 V1 标识

## 五、验证方法

### V1 验证
1. `cd v1/backend && python -m app.main` — 确认 DB 文件名为 `novel_generator_v1.db`
2. `curl http://localhost:8000/` — 返回包含 "V1" 的消息
3. `curl http://localhost:8000/api/v1/genres/list` — 正常返回
4. `cd v1/frontend && npm run dev` — 导航栏显示 "番茄小说生成器 V1"

### V2 验证
1. `cd v2/backend && python -m app.main` — 确认 DB 文件名为 `novel_generator_v2.db`
2. `curl http://localhost:8000/` — 返回包含 "V2" 的消息
3. `curl http://localhost:8000/api/v2/genres/list` — 正常返回
4. `curl http://localhost:8000/api/v2/refine/versions?novel_id=1` — 正常返回
5. `cd v2/frontend && npm run dev` — 导航栏显示 "番茄小说生成器 V2"

## 六、风险点

1. **V2 API 前缀变更**: 前端所有 API 调用需要同步修改，否则会导致 404
2. **DB 文件名变更**: 需要删除旧的 `novel_generator.db` 文件（或保留备份）
3. **CORS**: 无需修改（已设置 `allow_origins=["*"]`）
