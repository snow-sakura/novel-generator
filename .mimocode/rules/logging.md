# 日志记录规范

## 日志级别

| 级别 | 用途 | 示例 |
|------|------|------|
| DEBUG | 开发调试信息 | 变量值、函数调用 |
| INFO | 关键业务流程 | 请求处理、任务完成 |
| WARN | 潜在问题 | 配置降级、缓存未命中 |
| ERROR | 错误但可继续 | 请求失败、数据库错误 |
| FATAL | 严重错误需立即处理 | 系统崩溃、数据损坏 |

## 日志格式

```
[2024-01-01 12:00:00] [INFO] [request_id=abc123] [user_id=456] Message here
```

必须包含：
- 时间戳（ISO 8601 或可读格式）
- 日志级别
- 请求 ID（用于链路追踪）
- 有意义的消息

## 日志内容

### 必须记录
- 请求入口和出口
- 外部服务调用（请求和响应）
- 错误和异常（含堆栈）
- 关键业务操作（创建、修改、删除）
- 性能指标（慢查询、慢接口）

### 禁止记录
- 密码、Token 等敏感信息
- 完整的请求/响应体（可能含敏感数据）
- 循环中的大量重复日志
- 仅用于调试的临时日志

## 结构化日志

使用 JSON 格式便于检索：

```json
{
  "timestamp": "2024-01-01T12:00:00Z",
  "level": "ERROR",
  "message": "Payment failed",
  "request_id": "abc123",
  "user_id": "456",
  "error": "Insufficient funds",
  "stack": "..."
}
```

## 性能日志

- 慢查询日志（> 100ms）
- 慢接口日志（> 1s）
- 记录执行时间和资源使用

## 日志管理

- 生现环境使用日志收集系统（ELK/Loki）
- 设置日志轮转和过期策略
- 敏感日志脱敏处理
- 定期审查日志级别设置
