# Code Review 规范

## Review 检查清单

### 功能正确性
- 代码是否正确实现了需求？
- 边界条件是否处理？
- 错误路径是否覆盖？

### 代码质量
- 命名是否清晰表达意图？
- 函数是否遵循单一职责？
- 是否有重复代码可以提取？
- 复杂逻辑是否有注释说明 why？

### 安全性
- 用户输入是否验证和清洗？
- SQL 查询是否使用参数化？
- 敏感数据是否加密存储？
- 是否存在 XSS/CSRF 风险？

### 性能
- 是否有 N+1 查询问题？
- 大列表是否分页？
- 是否有不必要的内存分配？
- 数据库查询是否有索引支持？

### 可维护性
- 是否遵循项目现有模式？
- 是否有硬编码的魔法数字？
- 是否需要更新文档/注释？
- 测试是否覆盖核心逻辑？

## Review 原则

1. **先理解再评判** - 完整阅读变更再给意见
2. **指出问题而非人** - 评论代码，不评论开发者
3. **提供替代方案** - 指出问题时给出改进建议
4. **区分必须和建议** - 明确标注 blocking vs non-blocking
5. **保持简洁** - 评论精炼，避免噪音
