# 数据库设计与查询规范

## 表设计

### 命名规范
- 表名：小写复数，蛇形命名（`user_orders`）
- 主键：`id`（自增或 UUID）
- 外键：`{表名}_id`（`user_id`, `order_id`）
- 时间字段：`created_at`, `updated_at`, `deleted_at`
- 布尔字段：`is_` 前缀（`is_active`, `is_deleted`）

### 必要字段
每张表必须包含：
- `id` - 主键
- `created_at` - 创建时间
- `updated_at` - 更新时间
- `deleted_at` - 软删除时间（可选）

### 索引策略
- 外键字段必须建索引
- WHERE 条件常用字段建索引
- 排序字段建索引
- 避免过度索引（影响写入性能）
- 复合索引注意字段顺序（最左前缀原则）

## 查询规范

### 必须遵守
- 禁止 `SELECT *`，只查需要的字段
- 使用参数化查询，禁止字符串拼接
- 大表查询必须有 LIMIT
- 批量操作使用 Batch Insert/Update
- 避免在循环中执行 SQL

### 性能优化
- 使用 EXPLAIN 分析慢查询
- 避免子查询，优先使用 JOIN
- 分页查询使用游标分页（大偏移量场景）
- 读写分离（主库写，从库读）
- 热点数据使用缓存

### 事务规范
- 事务尽量短小
- 避免在事务中做 RPC 调用
- 使用合适的隔离级别
- 异常时确保事务回滚

## 迁移规范

- 每次迁移一个可回滚的变更
- 大表变更使用在线 DDL 工具
- 新增字段设置默认值
- 删除字段前先确认无引用
- 迁移脚本必须经过 Review
