## 1. 产品定位

**一句话**：用户输入一句「种子句」，系统通过多智能体协作自动生成完整网络小说（大纲 → 逐章正文 → 标题 → 导出）。

- **目标用户**：网文作者（提效）、内容工作室（批量）、写作爱好者（低门槛创作）
- **核心价值**：把「从 0 到 1 章」的时间从数小时压缩到数分钟；把「写完一本书」的流程自动化到只剩审校
- **交付形态**：
  1. 本地全栈应用（FastAPI + React，V1/V3 双版本）
  2. **在线 Demo**（GitHub Pages 纯静态，零安装体验全流程）

## 2. 用户故事（节选）

| 编号 | 作为… | 我希望… | 以便… | 验收 |
|------|-------|---------|-------|------|
| US-01 | 网文作者 | 输入一句话就能生成大纲和正文 | 快速验证脑洞 | 种子句 → 完整小说，全程 ≤ 章节数×分钟级，SSE 实时可见 |
| US-02 | 网文作者 | 生成中断后从断点继续 | 不浪费 Token 与时间 | 失败/取消记录可「继续生成」，已完成章节不重生成 |
| US-03 | 工作室运营 | 管理历史作品并可导出 | 归档分发 | 记录分页/搜索；导出 TXT/MD/PDF/EPUB/ZIP（Demo：TXT/MD/JSON） |
| US-04 | 新手 | 像聊天一样说需求 | 不用学表单 | 对话页多轮收集配置 → 看板同步 → 一键生成 |
| US-05 | 成本敏感用户 | 免费模型也能跑通 | 零成本体验 | 内置 OpenCode Zen 免费模型（MiMo V2.5 等）一键切换 |
| US-06 | 审阅者 | 跨章节人物/设定一致 | 长篇不崩 | 设定档案（Bible）注入每章生成上下文 |
| US-07 | 评估者 | 看到生成数据 | 评估质量 | 词频/角色出场/情感曲线统计（Demo：本地记录导出 JSON） |

## 3. 功能需求

### 3.1 核心生成管线（V1 起，P0）

| 编号 | 需求 | 说明 |
|------|------|------|
| F0-1 | 四智能体流水线 | ParserAgent（六维要素）→ OutlinerAgent（六层大纲）→ WriterAgent（逐章流式）→ TitlerAgent（书名） |
| F0-2 | SSE 流式输出 | token 级实时推送生成内容，前端进度条/章节状态实时更新 |
| F0-3 | 断点续写 | 中断/失败记录保存进度，支持从断点章节继续 |
| F0-4 | 多模型接入 | Provider 工厂模式：OpenAI 兼容接口 + OpenCode Zen + AGNES 等，配置持久化 |
| F0-5 | 记录与导出 | 生成记录落库；TXT/Markdown 导出（Demo 同步支持 JSON 记录导出） |

## 4. 非功能需求

| 类别 | 要求 | 现状 |
|------|------|------|
| 性能 | SSE 首 Token ≤ 5s；记录列表分页不阻塞 | ✅ |
| 可靠性 | 生成中断可恢复；全局异常统一 JSON | ✅ |
| 安全 | 密钥不入库不入仓；响应脱敏；CORS 白名单；请求体 ≤ 10MB；XSS 防护 | ✅ |
| 兼容 | Python ≥ 3.10；Node ≥ 18；现代浏览器（Demo 无框架依赖） | ✅ |
| 可观测 | 生成日志逐步可见（Demo 控制台日志区等价还原） | ✅ |
| 无障碍 | 键盘可达、对比度达标（v3.1.x 审计项） | ✅ |
