# novel-build-system 项目优化分析报告

> 分析日期：2026-07-27 ｜ 范围：项目结构 / v3 后端 / v3 前端（重点：前端设计与布局）

## 一、项目结构层面（P0）

### 1.1 版本目录冗余
- `v1/ v2/ v3/` 三个完整代码快照并列共存，git 共跟踪 458 个文件，v1/v2 已非活跃主线。
- **建议**：只保留 v3 作为主线，v1/v2 改为 git tag（如 `v1-archive`、`v2-archive`）后删除目录。

### 1.2 工程化设施缺失
- **无 `.gitignore`**：本地 `.env`（含密钥）有被误提交的风险。
- **无依赖锁文件**：后端只有 `requirements.txt`（无版本锁定），构建不可复现。
- **建议**：立即补 `.gitignore`（`.env`、`*.db`、`node_modules`、`docs/novel/` 生成产物）；后端迁移到 `uv`/`poetry` 锁定依赖。

### 1.3 docs 目录混乱
- 197 个文件中 145 个 `.txt` 是**生成的小说正文**、20 个 `.xmind` 是生成大纲——运行产物混入了文档目录。
- spec 文档分 v1/v2/v3 三套并存。
- **建议**：生成产物移到 `output/` 并 gitignore；spec 只保留 v3 版本。

### 1.4 文档与代码不符
- v3 README 宣称使用 CrewAI，但 `v3/backend/app/services/agents.py:5` 注明「CrewAI 依赖已移除」。
- `.env.example` 写 `DATABASE_URL=…v2.db`，而 `config.py:36` 默认 `v3.db`。

## 二、v3 后端（P1）

### 2.1 超大文件与耦合
| 文件 | 行数 | 问题 |
|---|---|---|
| `services/generator.py` | 704 | 生成主流程巨石化 |
| `routers/generate.py` | 673 | 路由层直接承载 SSE 生成业务逻辑 |
| `services/prompts.py` | 615 | 提示词硬编码堆积 |

**建议**：`generate.py` 路由只做参数校验 + 调 service；`generator.py` 按生成阶段（大纲/章节/润色）拆为子模块；prompts 外置为模板文件。

### 2.2 安全与健壮性
- `main.py` 中 `CORSMiddleware` 同时设 `allow_origins=["*"]` + `allow_credentials=True` —— 不安全且浏览器实际会拒绝，需收窄为具体前端域名。
- 无全局异常处理器（各路由散落 try/except，`generate.py` 有 31 处）。
- **测试完全缺失**（`routers/test.py` 只是 mock 数据接口，非测试）。

### 2.3 API 设计不统一
- 无统一 `/api/v1` 前缀；`/paragraphs/insert` 脱离 `/novels` 层级；`/analysis/{id}` 用 POST 做查询；工具端点（`/config/check`、`/cleanup`）与资源端点混杂。
- **建议**：统一为 `/api/v1/{resource}/{id}/{sub}`，工具类端点归入 `/api/v1/system/*`。

### 2.4 模型使用（符合国产化要求 ✅）
- 默认 `LLM_PROVIDER=opencode` + `deepseek-v4-flash-free`；`data.py` 内置 DeepSeek/通义/GLM/Kimi/豆包/文心/MiniMax/混元等 11 个国产 base_url。无硬编码密钥（已全仓扫描确认）。

### 3.2 重复代码
- Markdown 渲染器重复 **4 份**：`lib/utils.ts:85`、`CreatePage.tsx:89`、`NovelReader.tsx:7`、`ChatMessage.tsx:4` → 收敛为 1 份。
- `ensureTree` 在 `NovelPage.tsx:173` 与 `NovelStatusPanel.tsx:29` 重复。
- 「停止确认」弹窗在 CreatePage 与 ChatPage 几乎逐字重复。

### 3.3 安全与 Bug
- **XSS 风险**：`ChatMessage.tsx:43`、`NovelReader.tsx:263/543`、`CreatePage.tsx:42` 用自写正则 + `dangerouslySetInnerHTML` 渲染 AI 输出，未做 HTML 转义。建议换 `react-markdown` 或渲染前统一转义。
- **明显 Bug**：`novelStore.ts:45-49` 中 `LENGTH_RANGES.long` 与 `medium` 的 min/max 完全相同（2000/2500），复制粘贴错误。
- `prose prose-sm`（`ChatMessage.tsx:42`）无效——未安装 `@tailwindcss/typography`，AI 回复的代码块/列表全无样式。
- `api.ts` 残留 6 处 `console.log('[SSE]...')`。

### 3.4 性能与数据层
- 全程无 `React.memo`、无虚拟列表；长篇小说 NovelReader 全量渲染所有章节；zustand 全量订阅导致流式更新时整页重渲染。
- 无 react-query，所有请求手写 `useEffect+fetch`，`HistoryPage.tsx:57` 手写 `setInterval` 轮询且无竞态清理。
- **建议**：引入 `@tanstack/react-query`（缓存/轮询/重试）+ `react-virtuoso`（长列表）；zustand 用 selector 订阅。

### 3.5 依赖版本异常
- `vite 8.1.4` 配 `@vitejs/plugin-react 4.3.1` 不匹配；`typescript 7.0.2`、`@types/node 26.1.1` 版本号异常，需核实锁定。前端也缺 `package-lock.json`。

## 四、前端设计与布局优化（重点）⭐

### 4.1 现状
- 全局：sticky 顶栏 + `max-w-5xl` 居中，橘→玫红渐变品牌色，整体精致。
- CreatePage：桌面双栏（左 360px sticky 表单 + 右内容流）✅ 结构合理。
- ChatPage：左聊天流 + 右 `w-72` 状态面板（`lg` 以下直接隐藏）。
- NovelPage：**单列纵向堆叠** —— 功能 pill 一字排开（紫/琥珀/天蓝/玫红/翠绿 7 种颜色）+ 11 个浮层弹窗 + 信息卡/曲线/日志/大纲/正文全部串行堆叠。
- 无暗色模式（全仓 `dark:` 为 0 处）。

### 4.2 布局调整建议

**① NovelPage 重构为「三区工作台」布局（最高优先级）**
```
┌────────────────────────────────────────────┐
│  顶栏：返回 ｜ 书名 ｜ 导出/设置            │
├─────────┬──────────────────────┬───────────┤
│ 左侧栏   │   中间正文阅读区       │  右侧抽屉  │
│ 章节树   │   NovelReader        │  按需展开  │
│ 大纲导航 │   (独占视觉焦点)      │  分析/金句 │
│ 功能分组 │                      │  配图/TTS │
└─────────┴──────────────────────┴───────────┘
```
- 7 个彩色功能 pill → 收敛到左侧栏**分组菜单**（创作工具/分析洞察/多媒体），统一使用品牌橘色系 + 灰阶，仅激活态着色。
- 11 个弹窗 → 大部分改为**右侧抽屉（Drawer）**，保留上下文不打断阅读；仅确认类操作用 Dialog。
- 信息卡/情感曲线/日志 → 折叠进"创作过程"Tab，不再与正文抢占首屏。

**② 阅读体验强化**
- `max-w-5xl` 对读小说偏宽，正文区建议 `max-w-[70ch]`；增加字号/行距/背景色（米白/羊皮纸/夜间）阅读偏好设置。
- 章节切换从横向 tab 改为左侧章节树 + 上下章按钮，配合虚拟滚动。

**③ 视觉一致性**
- 建立统一 `<Modal>`/`<Drawer>`/`<Button>` 基础组件，消灭手写弹窗模板与内联样式（`CreatePage:501`、`NovelPage:624` 等 4 处内联 style）。
- 色彩规范：品牌橘为唯一主色，功能色只保留 成功/警告/危险 3 个语义色。
- `.novel-content` 中写死的 `#374151` 等 hex 改用 `novel.ink` token，贯通 tailwind 主题。

**④ 暗色模式 + 响应式补齐**
- tailwind `darkMode: 'class'` + token 化后成本很低，对"夜间读小说"场景价值极高。
- ChatPage 的状态面板与 CreatePage 的 TOC 在移动端不应直接 `hidden`，改为底部抽屉/浮动按钮唤出。
